# MVP-003 — تعریف گروه‌های روز و بازه‌های زمانی آموزشگاه

**وضعیت:** نهایی برای MVP  
**دامنه:** تنظیمات فرد/زوج، صبح/عصر و دسته‌بندی Slotهای زمان‌بندی  
**پیش‌نیاز:** [MVP-002 — محدودیت‌های ترجیحی](./MVP_002_scheduling_soft_constraints.md)  
**مالک تصمیم:** آموزشگاه / محصول آموزشی

---

## ۱. هدف

این سند تعریف دقیق و قابل تنظیم «روزهای فرد»، «روزهای زوج»، «صبح» و «عصر» را مشخص می‌کند. موتور زمان‌بندی و فلو دستی ساخت کلاس باید از یک منبع تنظیمات مشترک استفاده کنند تا معنای گروه‌ها در پیشنهاد خودکار، presetهای دستی، گزارش و نمایش برنامه یکسان باشد.

نام‌گذاری فرد و زوج در این سند یک قرارداد آموزشی است و از فرد یا زوج بودن عدد تاریخ تقویم استخراج نمی‌شود.

## ۲. تنظیمات پیش‌فرض

پیش‌فرض‌ها مطابق preset فعلی پروژه هستند:

| گروه                             | مقدار پیش‌فرض          |
| -------------------------------- | ---------------------- |
| روزهای زوج (`EVEN`)              | شنبه، دوشنبه، چهارشنبه |
| روزهای فرد (`ODD`)               | یکشنبه، سه‌شنبه        |
| روزهای خنثی/آخر هفته (`NEUTRAL`) | پنجشنبه، جمعه          |
| شروع بازه عصر                    | `14:00`                |
| منطقه زمانی                      | `Asia/Tehran`          |

نگاشت روزها به مقدار سیستمی:

| عنوان فارسی | مقدار سیستمی | گروه پیش‌فرض |
| ----------- | ------------ | ------------ |
| شنبه        | `SATURDAY`   | `EVEN`       |
| یکشنبه      | `SUNDAY`     | `ODD`        |
| دوشنبه      | `MONDAY`     | `EVEN`       |
| سه‌شنبه     | `TUESDAY`    | `ODD`        |
| چهارشنبه    | `WEDNESDAY`  | `EVEN`       |
| پنجشنبه     | `THURSDAY`   | `NEUTRAL`    |
| جمعه        | `FRIDAY`     | `NEUTRAL`    |

## ۳. مدل گروه‌بندی روزها

هر روز هفته باید دقیقاً عضو یکی از سه گروه زیر باشد:

- `EVEN`: روزهای زوج آموزشی؛
- `ODD`: روزهای فرد آموزشی؛
- `NEUTRAL`: روزهایی که در امتیاز تنوع فرد/زوج شرکت نمی‌کنند، مانند آخر هفته یا روز ویژه.

قواعد:

- یک روز نمی‌تواند هم‌زمان عضو بیش از یک گروه باشد.
- هیچ روزی نباید بدون گروه باقی بماند.
- هر دو گروه `EVEN` و `ODD` باید حداقل یک روز داشته باشند.
- گروه `NEUTRAL` می‌تواند خالی باشد.
- وجود روز در `NEUTRAL` به معنی تعطیل یا غیرقابل زمان‌بندی بودن آن نیست.
- فعال یا تعطیل بودن یک روز از Availability استاد، تقویم ترم و تنظیمات ساعات کاری تعیین می‌شود، نه از گروه فرد/زوج.
- آموزشگاه می‌تواند پنجشنبه را از `NEUTRAL` به `ODD` یا `EVEN` منتقل کند.

### اثر گروه خنثی بر امتیاز

- کلاس واقع‌شده در روز `NEUTRAL` یک پیشنهاد معتبر است.
- این کلاس پوشش دانش‌آموز، بار استاد و سایر معیارها را به‌صورت عادی محاسبه می‌کند.
- کلاس `NEUTRAL` نیاز تنوع فرد/زوج SC-002 را تأمین نمی‌کند.
- اگر فقط روزهای `NEUTRAL` راه‌حل معتبر داشته باشند، موتور آن‌ها را انتخاب می‌کند و هشدار `ODD_EVEN_DIVERSITY_UNAVAILABLE` می‌دهد.

## ۴. مدل گروه‌بندی صبح و عصر

در MVP، صبح و عصر با یک مرز زمانی تعریف می‌شوند:

```text
MORNING:  startTime < eveningStartsAt
EVENING:  startTime >= eveningStartsAt
```

مقدار پیش‌فرض `eveningStartsAt` برابر `14:00` است.

مثال با مرز `14:00`:

| ساعت شروع کلاس | گروه      |
| -------------- | --------- |
| `09:00`        | `MORNING` |
| `13:59`        | `MORNING` |
| `14:00`        | `EVENING` |
| `18:30`        | `EVENING` |

قواعد:

- دسته‌بندی فقط با `startTime` انجام می‌شود تا هر کلاس دقیقاً یک گروه داشته باشد.
- عبور زمان پایان کلاس از مرز، گروه آن را تغییر نمی‌دهد؛ کلاس `13:30–15:00` در گروه صبح است.
- مرز زمانی باید با قالب `HH:mm` ذخیره شود.
- مقدار مرز باید بین `10:00` و `18:00` باشد.
- این مرز ساعت کاری آموزشگاه را تعریف نمی‌کند؛ فقط برای دسته‌بندی و امتیاز تنوع استفاده می‌شود.
- کلاس خارج از ساعات کاری، در صورت تعریف ساعات کاری، توسط Hard Constraint جداگانه رد می‌شود.

## ۵. چهار گروه اصلی زمان‌بندی

ترکیب گروه روز و زمان شروع، گروه اصلی Slot را می‌سازد:

| گروه روز  | گروه زمان | گروه نهایی        |
| --------- | --------- | ----------------- |
| `ODD`     | `MORNING` | `ODD_MORNING`     |
| `ODD`     | `EVENING` | `ODD_EVENING`     |
| `EVEN`    | `MORNING` | `EVEN_MORNING`    |
| `EVEN`    | `EVENING` | `EVEN_EVENING`    |
| `NEUTRAL` | `MORNING` | `NEUTRAL_MORNING` |
| `NEUTRAL` | `EVENING` | `NEUTRAL_EVENING` |

چهار گروه اول مبنای SC-002 هستند. دو گروه خنثی برای گزارش و توضیح پیشنهاد نگهداری می‌شوند، اما خانه‌های هدف فرد/زوج را پر نمی‌کنند.

---

## ۶. کلاس‌های چندروزه

یک کلاس می‌تواند چند روز برگزاری در هفته داشته باشد. گروه‌بندی آن به شکل زیر انجام می‌شود:

- اگر همه روزهای کلاس در یک گروه روز باشند، کلاس همان گروه را می‌گیرد؛ برای مثال شنبه و دوشنبه برابر `EVEN` است.
- اگر روزهای کلاس ترکیبی از `ODD` و `EVEN` باشند، گروه روز کلاس `MIXED` است.
- اگر ترکیب شامل `NEUTRAL` و فقط یکی از `ODD` یا `EVEN` باشد، گروه غالب غیرخنثی برای گزارش استفاده می‌شود و وجود روز خنثی جداگانه ثبت می‌شود.
- اگر همه روزها `NEUTRAL` باشند، کلاس `NEUTRAL` است.
- کلاس `MIXED` برای هر دو محور فرد و زوج امتیاز کامل جداگانه ایجاد نمی‌کند؛ یک کلاس همچنان فقط یک گزینه دسترسی است.

برای MVP، موتور هنگام ساخت الگوهای چندجلسه‌ای ترجیح می‌دهد روزهای یک کلاس از یک گروه روز باشند. الگوهای `MIXED` معتبرند، اما در SC-002 فقط نصف امتیاز پوشش محور فرد/زوج را دریافت می‌کنند.

## ۷. مالکیت و سطح تنظیمات

- تنظیمات در سطح آموزشگاه ذخیره می‌شوند.
- تمام شعبه‌ها به‌صورت پیش‌فرض تنظیمات آموزشگاه را به ارث می‌برند.
- تنظیم جداگانه برای هر شعبه در MVP وجود ندارد.
- فقط کاربر دارای مجوز مدیریت تنظیمات آموزشگاه یا مجوز آینده `scheduling:settings` می‌تواند تنظیمات را تغییر دهد.
- سوپروایزر بدون مجوز تغییر، می‌تواند تنظیمات مؤثر را مشاهده کند.
- `SUPER_ADMIN` باید آموزشگاه هدف را صریح انتخاب کند.

---

## ۸. اعتبارسنجی تنظیمات

ذخیره تنظیمات فقط در صورت رعایت تمام قواعد زیر مجاز است:

1. هر هفت روز دقیقاً یک‌بار در یکی از گروه‌های `ODD`، `EVEN` یا `NEUTRAL` آمده باشند؛
2. اشتراک گروه‌ها خالی باشد؛
3. `ODD` و `EVEN` خالی نباشند؛
4. `eveningStartsAt` یک زمان معتبر با قالب `HH:mm` و در محدوده مجاز باشد؛
5. منطقه زمانی یک IANA Time Zone معتبر باشد؛
6. تنظیمات متعلق به همان آموزشگاهی باشند که کاربر اجازه مدیریت آن را دارد.

کدهای خطای پیشنهادی:

| کد                            | معنی                              |
| ----------------------------- | --------------------------------- |
| `SCHEDULE_DAY_DUPLICATED`     | یک روز در چند گروه قرار گرفته است |
| `SCHEDULE_DAY_MISSING`        | یک روز هیچ گروهی ندارد            |
| `ODD_OR_EVEN_GROUP_EMPTY`     | گروه فرد یا زوج خالی است          |
| `INVALID_EVENING_BOUNDARY`    | مرز صبح و عصر معتبر نیست          |
| `INVALID_SCHEDULING_TIMEZONE` | منطقه زمانی معتبر نیست            |

## ۹. اثر تغییر تنظیمات

- تغییر تنظیمات فقط روی اجرای جدید یا بازتولید بعدی اثر می‌گذارد.
- Scheduling Plan موجود نباید بدون درخواست کاربر دوباره دسته‌بندی یا امتیازدهی شود.
- هر Plan باید Snapshot گروه روزها، مرز صبح/عصر و منطقه زمانی استفاده‌شده را ذخیره کند.
- بازتولید Draft با تنظیمات جدید باید به کاربر اعلام کند که دسته‌بندی و امتیاز تنوع ممکن است تغییر کند.
- تغییرات باید با کاربر، زمان، مقدار قبلی و مقدار جدید در Audit Log ثبت شوند.
- گزینه «بازگردانی پیش‌فرض» باید تنظیمات جدول بخش ۲ را بازیابی کند.

## ۱۰. هماهنگی با فلو دستی فعلی

- preset فعلی `EVEN` باید به‌جای آرایه ثابت از تنظیمات آموزشگاه خوانده شود.
- preset فعلی `ODD` باید به‌جای آرایه ثابت از تنظیمات آموزشگاه خوانده شود.
- preset «آخر هفته» باید روزهای `NEUTRAL` را نمایش دهد؛ اگر این گروه خالی باشد، preset نمایش داده نمی‌شود.
- انتخاب مستقیم روزهای هفته در فلو دستی همچنان مجاز است.
- تغییر گروه‌بندی روزها نباید `daysOfWeek` یا `sessionDates` کلاس‌های موجود را تغییر دهد.
- برچسب فارسی و انگلیسی گروه‌ها باید از پیام‌های محلی‌سازی‌شده خوانده شود.
