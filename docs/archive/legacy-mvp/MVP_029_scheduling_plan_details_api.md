# MVP-029 — API جزئیات Plan زمان‌بندی

**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** بازیابی یک گزینه کامل و توضیح‌پذیر برای بررسی سوپروایزر

## Endpoint

```http
GET /scheduling/plans/:planId
```

مجوز لازم `VIEW_CLASSES` و ماژول لازم `CLASSES_COURSES` است. `SUPER_ADMIN` باید `instituteId` را در query مشخص کند؛ سایر نقش‌ها فقط می‌توانند Plan آموزشگاه موجود در JWT خود را بخوانند.

## محتوای پاسخ

قرارداد `SchedulingPlanDetailsSchema` موارد زیر را یکجا برمی‌گرداند:

- امتیاز، رتبه، شاخص کیفیت، پوشش و وضعیت Plan؛
- breakdown معیارها، Snapshot تنظیمات، هشدارها و کیفیت داده؛
- Proposalهای کلاس با استاد، سطح، شعبه، کلاس‌درس و Requirement؛
- امتیاز، دلایل انتخاب، هشدارها، وضعیت قفل و ویرایش هر Proposal؛
- جلسات پیشنهادی به ترتیب تاریخ و ساعت؛
- Requirementهای حل‌نشده همراه علت، تعداد کلاس کسری و سطح مرتبط؛
- اطلاعات Run، ترم و شعبه Plan.

Referenceهای نمایشی فقط فیلدهای لازم را شامل می‌شوند. برای مثال اطلاعات تماس استاد در پاسخ Plan افشا نمی‌شود.

## ترتیب پایدار

- Proposalها بر اساس `createdAt` و سپس `id`؛
- Sessionها بر اساس تاریخ، ساعت شروع و سپس `id`؛
- موارد حل‌نشده بر اساس `createdAt` و سپس `id`.

این ترتیب باعث می‌شود پاسخ API و رندر UI بین polling یا refresh جابه‌جا نشود.

## امنیت tenant

Plan با ترکیب `id` و `instituteId` و فقط از Run تکمیل‌شده خوانده می‌شود؛ بنابراین Draft موقت `PENDING_ENGINE` قابل بررسی به‌عنوان نتیجه نیست. علاوه بر آن، آموزشگاه Run، ترم، Proposalها، استاد، سطح، شعبه، کلاس‌درس، قفل‌کننده و Requirementهای مرتبط داخل شرط همان lookup کنترل می‌شود. شناسه معتبر به‌تنهایی اجازه دسترسی ایجاد نمی‌کند و Plan ناموجود یا دارای Reference خارج از tenant پاسخ یکسان دارد.

## معیار پذیرش

- [x] جزئیات یک Plan با endpoint محافظت‌شده قابل دریافت است.
- [x] Plan موقت یک Run تکمیل‌نشده به‌عنوان نتیجه قابل دریافت نیست.
- [x] Proposal، Session و Requirement حل‌نشده در یک پاسخ ارائه می‌شوند.
- [x] داده‌های توضیح‌پذیری MVP-010 بدون حذف قابل بازیابی‌اند.
- [x] نام‌های لازم برای UI بدون درخواست‌های N+1 ارائه می‌شوند.
- [x] ترتیب تمام collectionها پایدار است.
- [x] اطلاعات غیرضروری و حساس استاد افشا نمی‌شود.
- [x] lookup برای تمام نقش‌ها tenant-safe است.
- [x] ویرایش، انتخاب و انتشار Plan خارج از این مرحله باقی می‌مانند.
