**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** TypeScript و Zod مشترک بین API و رابط‌های کاربری  
**پیش‌نیاز:** [MVP-006](./MVP_006_student_time_profile.md)

## ۱. قراردادهای پایدار

مقادیر زیر به‌صورت `as const` در `@workspace/types` تعریف شده‌اند:

- وضعیت برنامه: `INCOMPLETE` و `COMPLETE`؛
- نوع بازه: `UNAVAILABLE` و `PREFERRED`؛
- منبع بازه: `SCHOOL`، `UNIVERSITY`، `WORK`، `PERSONAL` و `OTHER`.

Schemaهای خروجی، ورودی هر Constraint و عملیات جایگزینی کامل پروفایل زمانی نیز از همین پکیج export می‌شوند.

## ۲. قرارداد جایگزینی پروفایل

```ts
type ReplaceStudentTimeProfileInput = {
  scheduleStatus: "INCOMPLETE" | "COMPLETE"
  constraints: StudentTimeConstraintInput[]
}
```

`constraints` می‌تواند به‌صورت آرایه JSON یا رشته JSON در multipart FormData ارسال شود. رشته خالی به آرایه خالی تبدیل می‌شود تا پاک‌کردن کامل محدودیت‌ها صریح باشد.

## ۳. قواعد اعتبارسنجی

- `dayOfWeek` فقط یکی از روزهای هفته مشترک سامانه است.
- ساعت‌ها باید در قالب دقیق `HH:mm` باشند.
- `startTime` باید قبل از `endTime` باشد.
- بازه‌ها نیمه‌باز هستند؛ بنابراین پایان `14:00` و شروع بازه بعدی در `14:00` تداخل ندارد.
- تاریخ می‌تواند `Date`، تاریخ `YYYY-MM-DD` یا رشته تاریخ/زمان معتبر باشد.
- تاریخ تقویمی نامعتبر مانند `2026-02-31` رد می‌شود.
- `effectiveFrom` نباید بعد از `effectiveUntil` باشد.
- بازه‌های هم‌نوع در یک روز، ساعت و دوره اثرگذاری مشترک نباید هم‌پوشانی داشته باشند.
- بازه ترجیحی نباید با عدم دسترسی قطعی فعال در همان زمان هم‌پوشانی داشته باشد.
- ساعت یکسان در دوره‌های تاریخی جداگانه مجاز است.
- `COMPLETE` با فهرست خالی معتبر است و به معنی آزاد بودن کامل فراگیر است.

## ۴. محلی‌سازی خطاها

Factoryهای Schema پیام‌های اختیاری دریافت می‌کنند. بنابراین پکیج types متن فارسی یا انگلیسی را hardcode نمی‌کند و API یا UI می‌تواند پیام مناسب locale را تزریق کند.
