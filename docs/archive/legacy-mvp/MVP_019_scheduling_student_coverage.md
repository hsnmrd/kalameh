# MVP-019 — محاسبه پوشش زمانی دانش‌آموزان

**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** سنجش دسترسی دانش‌آموزان هر سطح به Feasible Assignmentهای زمان‌بندی

## جمعیت مبنا

فقط دانش‌آموز فعال مرتبط با Course موردنیاز و دارای `scheduleStatus: COMPLETE` وارد مخرج پوشش می‌شود. دانش‌آموز دارای برنامه `INCOMPLETE` یا بدون Student Profile از مخرج حذف و در `unknownStudentCount` گزارش می‌شود.

پروفایل `COMPLETE` بدون محدودیت به معنی آزاد بودن در تمام Slotهای قابل ارائه است.

## امکان حضور

دانش‌آموز برای یک Candidate پوشش‌داده‌شده محسوب می‌شود، مگر اینکه یک محدودیت `UNAVAILABLE` فعال داشته باشد که:

- روز هفته آن با Candidate یکسان باشد؛
- بازه مؤثر آن با بازه ترم اشتراک داشته باشد؛
- زمان آن با Candidate براساس قرارداد نیمه‌باز هم‌پوشانی داشته باشد.

محدودیت `PREFERRED` پوشش را کاهش نمی‌دهد و در امتیاز ترجیح زمانی مرحله بعد استفاده خواهد شد. بازه‌های مجاور، مانند عدم دسترسی تا `09:00` و شروع کلاس در `09:00`، متداخل نیستند.

## محاسبه

```text
candidateCoverage = coveredStudents / studentsWithKnownSchedule × 100
```

درصد با دقت دو رقم اعشار محاسبه می‌شود. اگر هیچ برنامه شناخته‌شده‌ای برای Course وجود نداشته باشد، وضعیت `NOT_APPLICABLE` و درصد `null` است؛ صفر نمایش داده نمی‌شود.

برای هر Course علاوه بر نتیجه هر Candidate، تعداد دانش‌آموز شناخته‌شده و ناشناخته، بهترین پوشش قابل دستیابی و تعداد Candidateها گزارش می‌شود. Course بدون Candidate نیز در خروجی باقی می‌ماند.

## تکرارپذیری و اعتبار قرارداد

- دانش‌آموز و Assignment تکراری فقط یک‌بار محاسبه می‌شوند؛
- خروجی براساس شناسه و `assignmentKey` مرتب می‌شود؛
- قرارداد Zod سازگاری تعداد افراد، درصد، وضعیت `APPLICABLE` و summary را بررسی می‌کند؛
- شناسه دانش‌آموزان پوشش‌داده‌شده و پوشش‌نیافته برای محاسبه پوشش یکتا در ترکیب چند کلاس حفظ می‌شود.

## معیار پذیرش

- [x] فقط دانش‌آموزان دارای برنامه کامل وارد مخرج می‌شوند.
- [x] `UNAVAILABLE` فعال، امکان استفاده از Candidate متداخل را حذف می‌کند.
- [x] `PREFERRED` به‌اشتباه به‌عنوان عدم دسترسی استفاده نمی‌شود.
- [x] بازه مؤثر محدودیت و مرز نیمه‌باز زمان رعایت می‌شود.
- [x] داده ناشناخته جداگانه گزارش می‌شود.
- [x] نبود داده شناخته‌شده `NOT_APPLICABLE` است.
- [x] بهترین پوشش هر Course و Course بدون Candidate گزارش می‌شود.
- [x] در این مرحله Proposal یا Class واقعی ساخته نمی‌شود.
