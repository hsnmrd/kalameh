# MVP-030 — انتخاب و بازبینی دستی Plan

**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** انتخاب گزینه، ویرایش تخصیص و قفل‌کردن Proposal

## Endpointها

```http
POST  /scheduling/plans/:planId/select
PATCH /scheduling/plans/:planId/proposals/:proposalId
PATCH /scheduling/plans/:planId/proposals/:proposalId/lock
```

تمام عملیات به مجوز `MANAGE_CLASSES` و ماژول `CLASSES_COURSES` نیاز دارند. `SUPER_ADMIN` باید `instituteId` هدف را در query ارسال کند.

## انتخاب Plan

فقط Plan متعلق به Run تکمیل‌شده و دارای وضعیت `DRAFT` یا `SELECTED` قابل انتخاب است. انتخاب جدید در یک transaction، انتخاب قبلی همان Run را به `DRAFT` برمی‌گرداند و زمان شروع اولین بازبینی را حفظ می‌کند.

## ویرایش Proposal

فیلدهای قابل ویرایش شامل عنوان، استاد، شعبه، کلاس‌درس، ظرفیت، نوع برگزاری، روزها و ساعت شروع/پایان هستند. قبل از ذخیره موارد زیر کنترل می‌شوند:

- استاد فعال، tenant-safe و دارای Qualification همان Course؛
- شعبه و کلاس‌درس فعال و متعلق به آموزشگاه؛
- ظرفیت و شعبه کلاس‌درس سازگار؛
- کلاس آنلاین بدون اتاق و کلاس حضوری دارای اتاق؛
- بازه ساعت معتبر.

ویرایش، امتیاز Proposal و Plan را stale می‌کند، `manualEditCount` و `editCount` را افزایش می‌دهد و دلیل `MANUALLY_SELECTED` و هشدار `MANUAL_EDIT_REQUIRES_VALIDATION` را ثبت می‌کند. اعتبارسنجی کامل تداخل‌ها و Hard Constraintهای کل Plan در MVP-031 انجام می‌شود.

## قفل Proposal

قفل، شناسه کاربر و زمان قفل را ثبت می‌کند. بازکردن قفل هر دو مقدار را پاک می‌کند. Proposal قفل‌شده در درخواست regeneration بعدی قابل حفظ است. قفل‌کردن امتیاز را نامعتبر نمی‌کند.

## قواعد lifecycle

- فقط Run با وضعیت `COMPLETED` قابل بازبینی است.
- فقط Planهای `DRAFT` و `SELECTED` قابل تغییرند.
- Proposal منتشرشده قابل ویرایش یا قفل‌کردن نیست.
- تمام mutationها با guard مجدد داخل transaction اجرا می‌شوند.
- انتخاب، ویرایش، قفل و بازکردن قفل Audit Log مستقل دارند.
