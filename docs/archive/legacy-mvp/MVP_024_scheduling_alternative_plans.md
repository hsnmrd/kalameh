# MVP-024 — تولید گزینه‌های جایگزین برنامه

**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** تولید حداکثر سه composition متمایز و رتبه‌بندی آن‌ها

## هدف

سوپروایزر نباید فقط یک پاسخ غیرقابل‌مقایسه دریافت کند. این مرحله براساس `alternativePlanCount` بین یک تا سه Plan متمایز تولید می‌کند و آن‌ها را با قرارداد قطعی MVP-022 رتبه‌بندی می‌کند.

## روش تولید

1. Composer‌ MVP-023 بدون exclusion اجرا و Plan پایه ساخته می‌شود.
2. برای ساخت شاخه بعدی، هر assignment انتخاب‌شده به‌ترتیب پایدار exclude می‌شود.
3. هر composition جدید نیز می‌تواند شاخه exclusion بعدی بسازد.
4. Planها براساس مجموعه canonical از `assignmentKey`ها deduplicate می‌شوند.
5. جست‌وجو با رسیدن به تعداد درخواستی، خالی‌شدن صف یا سقف ۱۰۰ تلاش متوقف می‌شود.

این روش برای MVP یک جست‌وجوی bounded و قابل پیش‌بینی است؛ exhaustive solver محسوب نمی‌شود.

## رتبه‌بندی

خروجی‌های متمایز به `SchedulingDeterministicRankingService` داده می‌شوند. دروازه ۵ واحد درصدی پوشش و تمام tie-breakهای MVP-022 روی گزینه‌ها اعمال می‌شوند و فقط رتبه اول `isRecommended` است.

معیار بار استاد هنوز در Composer محاسبه نشده و تا اضافه‌شدن معیار مربوط، مقدار خنثی یکسان برای همه گزینه‌ها دارد؛ بنابراین روی ترتیب فعلی اثر نمی‌گذارد.

## رفتار کمبود گزینه

اگر تعداد composition متمایز کمتر از مقدار درخواستی باشد، همان تعداد واقعی بازگردانده می‌شود. Plan ناقص یا کاملاً حل‌نشده نیز یک خروجی معتبر و توضیح‌پذیر است و صرفاً برای پرکردن تعداد، duplicate ساخته نمی‌شود.

## مرز مرحله

- هیچ رکورد دیتابیس یا Class ساخته نمی‌شود.
- خروجی آماده مرحله persistence آینده است.
- `searchAttemptCount` و `searchLimitReached` برای مشاهده‌پذیری جست‌وجو ثبت می‌شوند.

## معیار پذیرش

- [x] تعداد درخواستی فقط عدد صحیح بین ۱ و ۳ است.
- [x] Planهای تکراری وارد خروجی نمی‌شوند.
- [x] exclusionها و صف جست‌وجو ترتیب پایدار دارند.
- [x] خروجی با تغییر ترتیب candidateها تغییر نمی‌کند.
- [x] Planها با سرویس قطعی MVP-022 رتبه‌بندی می‌شوند.
- [x] کمبود گزینه با خروجی کوتاه‌تر، نه duplicate، مدیریت می‌شود.
- [x] جست‌وجو سقف تلاش صریح دارد.
- [x] این مرحله هیچ داده‌ای ذخیره نمی‌کند.
