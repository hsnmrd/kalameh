# MVP-018 — فیلتر Hard Constraint کاندیدهای زمان‌بندی

**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** حذف Slotهای نامعتبر و تولید تخصیص‌های قابل استفاده برای مراحل امتیازدهی

## ارزیابی کاندید

هر Candidate تولیدشده در MVP-017 پیش از ورود به امتیازدهی از فیلترهای زیر عبور می‌کند:

1. Requirement متناظر، Course، شعبه و مدت جلسه همچنان معتبر باشند؛
2. Qualification به همان استاد و Course تعلق داشته باشد و استاد فعال، دارای نقش `TEACHER` و سازگار با شعبه باشد؛
3. کل بازه Candidate داخل Availability مرجع استاد باشد؛
4. استاد در Class واقعی همان روز و ساعت تداخل نداشته باشد؛
5. برای کلاس حضوری، اتاق فعال، سازگار با شعبه و دارای ظرفیت کافی وجود داشته باشد؛
6. اتاق انتخابی در Class واقعی همان روز و ساعت تداخل نداشته باشد؛
7. کلاس آنلاین هیچ اتاقی اشغال نکند.

تداخل زمانی با قرارداد نیمه‌باز `startA < endB && startB < endA` محاسبه می‌شود؛ بنابراین دو کلاس که یکی دقیقاً هنگام پایان دیگری شروع شود متداخل نیستند. برای تطابق روز از `daysOfWeek` و در صورت وجود از روز هفته‌ی `sessionDates` ساخت‌یافته استفاده می‌شود.

## اتاق و تخصیص

هر Slot حضوری می‌تواند برای چند اتاق معتبر به چند Feasible Assignment تبدیل شود. اتاق‌های نامعتبر یا متداخل حذف می‌شوند، اما وجود یک اتاق آزاد برای معتبر ماندن Candidate کافی است. Candidate آنلاین دقیقاً یک Assignment با `classroomId: null` می‌سازد.

## خروجی توضیح‌پذیر

خروجی شامل `accepted`، `rejected` و summary شمارشی است. کدهای رد عبارت‌اند از:

- `INCOMPLETE_CLASS_REQUIREMENT`
- `INVALID_TEACHER`
- `TEACHER_NOT_QUALIFIED`
- `OUTSIDE_TEACHER_AVAILABILITY`
- `TEACHER_TIME_CONFLICT`
- `INVALID_DELIVERY_LOCATION`
- `INSUFFICIENT_CLASSROOM_CAPACITY`
- `CLASSROOM_TIME_CONFLICT`

قرارداد Zod سازگاری شمارنده‌ها با خروجی واقعی و سازگاری نوع برگزاری با `classroomId` را کنترل می‌کند.

## مرز این مرحله

این سرویس Hard Constraintهای سطح Slot را اعمال می‌کند. تداخل بین Proposalهای انتخاب‌شده در یک Plan، تعداد جلسات، تاریخ‌های واقعی ترم و بررسی نهایی داده زنده در مراحل ترکیب برنامه و انتشار دوباره اعمال خواهند شد. در MVP-018 هنوز Proposal یا Class ذخیره نمی‌شود.
