# MVP-027 — اجرای پس‌زمینه موتور زمان‌بندی

**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** اتصال Runهای `QUEUED` به Orchestrator موتور تولید

## هدف

`SchedulingGenerationDispatcherService` از جدول `SchedulingRun` به‌عنوان صف پایدار استفاده می‌کند. در نتیجه درخواست HTTP فقط Run و Snapshotهای آن را ثبت می‌کند و تولید برنامه خارج از چرخه پاسخ HTTP انجام می‌شود.

## رفتار worker

- با بالا آمدن API، صف بلافاصله و سپس هر دو ثانیه بررسی می‌شود.
- در هر نوبت حداکثر ۵ Run، به ترتیب `createdAt` و سپس `id`، پردازش می‌شوند.
- Runها به‌صورت ترتیبی پردازش می‌شوند تا یک batch فشار کنترل‌نشده روی دیتابیس ایجاد نکند.
- شکست یک Run مانع پردازش Run بعدی نمی‌شود.
- پس از ثبت یک درخواست موفق، dispatcher بیدار می‌شود تا منتظر poll بعدی نماند.

## اجرای امن در چند instance

خواندن صف در سطح platform فقط `id` و `instituteId` را برمی‌گرداند. سپس Orchestrator هر Run را با شرط اتمیک زیر claim می‌کند:

```text
id = runId
instituteId = instituteId
status = QUEUED
```

اگر instance دیگری زودتر Run را claim کرده باشد، نتیجه `skipped` محسوب می‌شود. بنابراین اجرای چند API instance باعث تولید تکراری یک Run نمی‌شود.

## بازیابی پس از restart

Runهایی که بیش از ۳۰ دقیقه در وضعیت `GENERATING` مانده‌اند، با guard شامل `id`، `instituteId`، وضعیت و زمان شروع دوباره به `QUEUED` برگردانده می‌شوند. رویداد `GENERATION_REQUEUED` نیز برای آن‌ها در Audit Log ثبت می‌شود. این مسیر فقط crash یا توقف ناگهانی worker را بازیابی می‌کند؛ خطاهای عادی موتور همچنان به `FAILED` می‌روند.

## قرارداد نتیجه batch

`SchedulingDispatchResultSchema` شمارنده‌های زیر را کنترل می‌کند:

- Runهای کشف‌شده؛
- Runهای تکمیل‌شده؛
- Runهای شکست‌خورده؛
- Runهای skip‌شده به علت claim هم‌زمان؛
- Runهای stale که دوباره صف‌شده‌اند.

مجموع تکمیل‌شده، شکست‌خورده و skip‌شده باید دقیقاً با تعداد Runهای کشف‌شده برابر باشد.

## معیار پذیرش

- [x] Runهای صف‌شده بدون نگه‌داشتن درخواست HTTP پردازش می‌شوند.
- [x] polling هم‌پوشان در یک instance ادغام می‌شود.
- [x] claim اتمیک Orchestrator از اجرای تکراری بین instanceها جلوگیری می‌کند.
- [x] شکست یک Run، batch را متوقف نمی‌کند.
- [x] Runهای گیرکرده پس از timeout بازیابی می‌شوند.
- [x] بازیابی stale به‌صورت tenant-scoped و قابل ممیزی است.
- [x] shutdown تایمر worker را متوقف می‌کند.
- [x] ایجاد و انتشار `Class` همچنان خارج از این مرحله باقی می‌ماند.
