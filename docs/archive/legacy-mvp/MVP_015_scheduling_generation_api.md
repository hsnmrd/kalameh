# MVP-015 — API تولید برنامه پیشنهادی

**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** ثبت درخواست تولید، Snapshot ورودی و ساخت پیش‌نویس مستقل از کلاس واقعی

## قرارداد API

`POST /scheduling/plans/generate`

این endpoint به مجوز `classes:manage` و ماژول `CLASSES_COURSES` نیاز دارد. ورودی شامل آموزشگاه هدف برای `SUPER_ADMIN`، ترم، شعبه اختیاری، شناسه نیازهای کلاسی، تعداد گزینه‌های درخواستی و اطلاعات بازتولید اختیاری است.

## رفتار

سرویس پیش از ثبت درخواست، مالکیت آموزشگاه و تطابق ترم، شعبه، نیازهای فعال، اجرای مبدا و پیشنهادهای قفل‌شده را کنترل می‌کند. سپس داده‌های زیر را با ترتیب پایدار Snapshot می‌گیرد:

- ترم، شعبه و نیازهای کلاسی انتخاب‌شده؛
- صلاحیت‌ها و Availability استادان مرتبط؛
- وضعیت برنامه و محدودیت‌های زمانی زبان‌آموزان سطح‌های مرتبط؛
- کلاس‌های واقعی همان ترم برای بررسی تداخل و بار فعلی؛
- اتاق‌های فعال مرتبط؛
- وزن‌ها، گروه‌های زمانی و نسخه فرمول مؤثر.

پس از موفقیت preflight، در یک nested write اتمیک، یک `SchedulingRun` با وضعیت `QUEUED` و یک `SchedulingPlan` با وضعیت `DRAFT` ساخته می‌شود. Plan اولیه با هشدار `GENERATION_PENDING` مشخص است و تا اضافه‌شدن موتور زمان‌بندی در MVP-017 به بعد Proposal ساختگی ندارد. در صورت وجود خطای مسدودکننده، Run با وضعیت `PREFLIGHT_FAILED` و بدون Plan ذخیره می‌شود.

## مرز ایمنی

این endpoint هیچ رکوردی در `Class` ایجاد نمی‌کند. تبدیل Proposalهای تاییدشده به کلاس واقعی فقط در فلو انتشار مستقل انجام خواهد شد.

تنظیمات فعلی از مقادیر پیش‌فرض MVP Snapshot می‌شوند و فیلد `instituteOverrideApplied` این موضوع را صریح ثبت می‌کند. پس از اضافه‌شدن ذخیره تنظیمات قابل ویرایش آموزشگاه، همین نقطه تنظیمات مؤثر آموزشگاه را بدون تغییر قرارداد Plan ثبت خواهد کرد.
