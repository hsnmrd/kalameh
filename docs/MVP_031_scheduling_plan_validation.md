# MVP-031 — اعتبارسنجی نهایی Plan

**وضعیت:** پیاده‌سازی‌شده  
**دامنه:** بررسی مجدد Hard Constraintها با داده زنده، بدون انتشار Class

## Endpoint

```http
POST /scheduling/plans/:planId/validate
```

فقط Plan با وضعیت `SELECTED` از Run تکمیل‌شده قابل اعتبارسنجی است. مجوز لازم `MANAGE_CLASSES` است و `SUPER_ADMIN` باید آموزشگاه هدف را مشخص کند.

## کنترل‌های زنده

- مالکیت tenant تمام مراجع؛
- فعال‌بودن ترم، شعبه، استاد، Requirement و کلاس‌درس؛
- نقش و Qualification استاد برای سطح؛
- قرارگیری کامل زمان در Availability استاد؛
- اعتبار بازه زمان و مدت جلسه؛
- سازگاری نوع برگزاری، شعبه، اتاق و ظرفیت؛
- cadence تعریف‌شده در Requirement؛
- یکتایی، روز هفته و بازه ترم برای Sessionها؛
- تداخل استاد و اتاق با Classهای واقعی همان ترم؛
- تداخل بین Proposalهای خود Plan.

هم‌جواری بازه‌ها تداخل نیست و قرارداد نیمه‌باز `[start, end)` رعایت می‌شود.

## پاسخ

`SchedulingPlanValidationSchema` شامل `isValid`، زمان اعتبارسنجی، تعداد Proposalها و فهرست ساختاریافته تخلف‌هاست. هر تخلف دارای کد پایدار، Proposal مربوط، شناسه موجودیت‌های متداخل و context است. پاسخ نامعتبر باعث ساخت یا تغییر Class نمی‌شود.

هر اجرا با `PLAN_VALIDATION_PASSED` یا `PLAN_VALIDATION_FAILED` در Audit Log ثبت می‌شود.

## مرز انتشار

نتیجه این endpoint برای بازبینی UI است و مجوز انتشار دائمی محسوب نمی‌شود؛ MVP-032 همین validator را در لحظه انتشار دوباره اجرا خواهد کرد تا تغییر داده بین validate و publish باعث race نشود.
